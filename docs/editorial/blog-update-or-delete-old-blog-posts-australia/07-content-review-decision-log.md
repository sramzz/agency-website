# Content review decision log

An original worksheet for reviewing existing business articles. Use it alongside **Should You Update or Delete Old Blog Posts? A Practical SEO Guide**. It supports judgement; it does not automatically score pages or determine whether they should be removed.

## 1. Define the review

| Field | Your record |
|---|---|
| Website or section reviewed | |
| Review owner and contributors | |
| Review date and reason | |
| Audience and business purpose | |
| Scope and pages excluded | |
| Available evidence and access limitations | |
| Comparison periods and reason for choosing them | |
| Other changes or seasonal factors | |

Do not enter missing data as zero. Distinguish search clicks, website sessions, recorded enquiries and customers. A page's supporting role needs evidence; a plausible role is not a measured conversion.

## 2. Complete one record per existing address

| Field | Your record |
|---|---|
| Existing URL and page title | |
| The specific reader question it answers | |
| Is the information accurate and still relevant? What was checked? | |
| Original information, historical context or useful material to preserve | |
| Search evidence: source, dates, filters, observations | |
| Website or operational evidence: source, units, dates, observations | |
| Internal references and available external-link evidence | |
| Technical/indexing issues that need separate investigation | |
| Missing evidence and how it could affect the decision | |
| Content decision: keep / update / combine / remove / investigate first | |
| Specific reason; reasonable alternatives considered | |
| Proposed content work, including material to preserve | |
| URL action: retain / relevant permanent redirect / 404 or 410 / investigation | |
| Replacement destination, if any, and why it fulfils the old need | |
| Person responsible for the decision | |
| Implementation owner and authorised scope | |
| Working copy or recovery record, where appropriate | |
| Expected reader benefit and how it could be checked | |
| Planned verification and follow-up date, with rationale | |

For a combination, create records for each existing address and identify one destination. Do not assume similar keywords mean the pages serve the same purpose. Do not choose an irrelevant redirect merely because the old page has backlinks.

“Investigate first” leaves the decision open. Identify what must be checked and who will do it. It is not permission to remove the page while the evidence is missing.

## 3. Record implementation separately from the proposal

| Field | Actual record — complete after implementation |
|---|---|
| What was changed and when | |
| Address tested and observed HTTP response | |
| Redirect destination reached, where applicable | |
| Content, links and next step checked | |
| Affected sitemap/canonical references checked | |
| Issues found and corrective action | |
| Person who verified and evidence location | |

An expected status code or a redirect configuration is not an observed test result. A screenshot of the page alone does not establish its HTTP response.

## 4. Record follow-up observations

| Field | Actual observation — leave blank until measured |
|---|---|
| Follow-up period and comparable baseline | |
| Search observations, with sources and filters | |
| Relevant website or operational observations, with units | |
| Combined source/destination view for a consolidation | |
| Other changes that may explain the difference | |
| What is supported; what remains uncertain | |
| Next decision, owner and reason | |

Do not label a before-and-after change as a proven causal effect. Check which URL the source attributes activity to before aggregating figures, so you do not double-count data represented under a canonical URL. Do not promise a ranking recovery date. For a page serving a narrow or seasonal need, choose a period that can reasonably capture that need.

## 5. Worked decisions: fictional examples

The following cases illustrate how to reason. They are not a review of a live website, client results, measured traffic or executed changes. The descriptions supply the scenario facts; implementation and follow-up remain unobserved.

| Case | Scenario facts | Editorial decision | Proposed URL action | Verification still needed |
|---|---|---|---|---|
| A — Accurate older guide | A preparation guide still answers a distinct customer question; its instructions have been checked and remain correct | Keep; record review rather than manufacture a new publication date | Retain the existing address | Check referenced pages and reader next step; no live test recorded here |
| B — Changed submission route | A quote guide concerns a current service, but describes submission steps that the business has changed | Update the obsolete steps and check surrounding references | Retain the existing address | Test the route described and confirm the visible article matches it |
| C — Same task in two guides | A content comparison confirms that two quote-preparation guides address the same service, audience and task; both contain details worth preserving | Combine useful details into one clear answer | Select and verify the destination; permanently redirect the retired address only if the replacement fulfils its need | Check preserved details, destination, response, links and affected sitemap/canonical references |
| D — Expired one-off offer | A reviewed offer has ended; no continuing reader purpose, archive value or equivalent replacement has been identified | Remove after documenting what is lost and the decision owner | Return an appropriate 404 or 410; no irrelevant redirect | Check response and links under the website's control; preserve an appropriate working record if needed |
| E — Incomplete evidence | A guide appears quiet, but analytics access is missing and indexing is unchecked | Investigate first; do not treat missing evidence as zero value | Retain pending investigation; no removal action approved in this example | Obtain appropriate evidence, check indexing and re-evaluate purpose |
